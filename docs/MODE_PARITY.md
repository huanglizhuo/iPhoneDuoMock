# 网页与截图模式对齐

## 本轮根因

网页原先位于 WebGL 画布上方，只通过外屏二维轮廓加粗 6 px 排除遮挡。它不知道前方金属框、铰链和摄像头的深度，因此把后方网页画在了前方机身上。之前的轮廓连续性修复只能消除屏幕接缝，不能处理三维遮挡。

播放入口调用 changeMode('animation') 后修改 scene，预览帧与导出也分别将 scene 强制为 fold。场景、屏幕方向、素材检查及文件名因此可能与用户选择不一致。

## 逐项对照

| 项目 | 截图制作 | 网页模拟 | 本轮处理 |
| --- | --- | --- | --- |
| 设备网格、骨骼、相机 | DeviceRenderer | 同一个 DeviceRenderer | 继续共用 |
| 机身与屏幕遮挡 | GPU 深度测试 | 原为二维近似裁切 | 网页改用同一模型的 GPU 深度可见性遮罩 |
| 摄像头、边框、铰链 | 实体网格覆盖屏幕 | 原可被 iframe 覆盖 | 全部网格参与遮挡，屏幕按 RGB ID 区分 |
| 交互命中区域 | 画布拖动 | iframe 内交互 | 使用可见性遮罩生成点击裁切，隐藏网页不拦截机身区域 |
| 六种姿态 | scene | scene | 统一保留所选姿态 |
| 播放、暂停、时间轴 | 同一控件 | 同一控件 | 移除所有强制 fold；切换场景清零旧时间并暂停 |
| 当前预览帧 | 曾独立计算 | 曾独立计算 | 统一 projectAt(project, time) |
| 动画导出帧 | 曾独立计算并重置场景 | 不直接导出 iframe | 截图导出也使用 projectAt，并保留场景 |
| 内外屏方向和素材 | 曾在设备渲染中判断 | 曾在网页视口中重复判断 | 统一 screenSlots(scene) |
| 缺图校验 | 静态按场景，动画曾按 fold | 不适用图片校验 | 动画检查当前姿态实际使用的内外屏槽位 |
| 预览标题和导出文件名 | 动画曾固定 UNFOLD/fold | 同样存在固定标签 | 显示所选场景；视频/GIF 文件名使用该场景 |
| 背景、机身颜色、缩放、镜头 | 共用控件 | 共用控件 | 保持一致 |
| 网页操作与机身旋转 | 上传图片无页面交互 | 可切换操作网页/旋转设备 | 保留必要的模式差别 |
| 输出 | PNG/视频/GIF/ZIP | 授权捕获当前标签页后使用同一导出管线 | 临时截图仅在本地内存中处理 |

## 代码整理

- ScreenVisibility 单独管理 GPU ID 渲染、深度遮挡、遮罩编码与点击裁切；使用可复用 render target，退出时释放资源。一次渲染区分外屏、内屏左右两半，不为每个姿态写特殊遮挡规则。
- browser.ts 只负责网页逻辑尺寸与内容平面投影，移除手工边界追踪和凸包裁切。
- screenSlots 集中确定内外屏槽位，由渲染器、网页控制和动画校验共用。
- projectAt 集中计算当前动画帧，预览与导出不再各自更改场景。
- 设备画布与 DOM 遮罩在同一次绘制中提交，避免新机身配上旧遮罩的一帧闪烁。

## 仍然不同的部分

截图是 WebGL 纹理；网页是浏览器实际文档。网页的侧向覆盖及局部滤镜仍不等同于截图 shader 的逐像素采样。跨域 iframe 不允许读取并同步内部状态，静态弯折内屏分片仍是独立文档。网站的禁止嵌入策略仍然有效。本次解决的是设备遮挡、播放状态、素材方向和共享交互，不声称模拟完整的 iOS 浏览器或系统折叠事件。

## 回归中发现的附加问题

骨骼动画后原来只更新 bounding box，未更新 skinned mesh 的 bounding sphere。切换开合角度并偏转相机后，射线测试会漏掉已移动的屏幕网格，也存在渲染裁剪使用旧边界的风险。现在每帧同时更新两者。

遮罩不仅用于绘制：从同一可见像素生成 iframe 的点击裁切，完全被遮挡的屏幕隐藏并退出 Tab 焦点。这样网页既不会覆盖机身，也不会在不可见区域拦截点击。

复现与验证用例：`tests/browser-occlusion.spec.ts` 使用真实模型射线与屏幕可见像素比较，覆盖六种姿态 × 三个开合角度，包含偏转镜头，并要求每组仍有可见网页内容；播放用例同时覆盖两个工作区的竖屏、坐姿和站立。
